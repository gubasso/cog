# Guides

Task-oriented documentation for `<project>`: how to complete a specific job. A guide promises
sequence and completion. It states prerequisites, the steps, and how to verify the result.

A guide links to reference material instead of embedding complete tables. If a guide starts saying
"we always do X because Y", the durable *why* belongs in a lean ADR under
[`../decisions/`](../decisions/) and the guide should link to it.

Name guides for the task: `<task>-runbook.md`, `add-a-note.md`, `promote-a-draft.md`.
