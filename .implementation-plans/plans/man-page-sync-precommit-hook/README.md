# Enforce man/cog.1 ↔ man/cog.1.scd Sync via a cog Command + Pre-commit Hook

> Plan: man-page-sync-precommit-hook | Complexity: S | Rounds: 1 | Generated: 2026-06-18 | Repo: /workspaces/cog

## Problem Statement

`man/cog.1` is a generated artifact (header: `.\" Generated by scdoc 1.11.4`) produced from `man/cog.1.scd` by `scdoc`. It is **committed** to the repo on purpose: `install.sh` prefers a prebuilt `man/cog.1` when `scdoc` is unavailable at install time, so the committed copy is a distribution fallback, not a throwaway.

The problem: nothing keeps the committed `man/cog.1` in sync with `man/cog.1.scd`. Today:

- `just man` (justfile:44-50) is the **only** definition of how the page is built (`scdoc < man/cog.1.scd > man/cog.1`), and it silently exits 0 when `scdoc` is missing.
- `test/integration/help_snapshots.bats:286-292` only checks that `man/cog.1.scd` _lists every command_ — it does **not** verify that the generated `man/cog.1` byte-matches `scdoc(man/cog.1.scd)`.

So a contributor can edit `man/cog.1.scd`, forget to run `just man`, and commit a stale `man/cog.1`. No gate catches it.

This plan closes the gap by making one `cog` subcommand the **single source of truth** for man-page generation/verification, wiring it into pre-commit as the enforcing gate, and making `just man` delegate to that hook (matching how `just lint`/`just test` already delegate to `pre-commit run`).

## Decisions & Constraints

- **Executor: executor-prex (EF 1.5).**
- **New command `cog man-build`** owns the deterministic scdoc mechanic (the repo's skill/script boundary requires deterministic mechanics live in `cog` subcommands, not in justfile prose or skills). It supports two modes:
  - default (no flag): regenerate `man/cog.1` from `man/cog.1.scd` (atomic write).
  - `--check`: regenerate to a temp file, compare to the committed `man/cog.1`, fail on drift, never write. Used by CI/tests for a read-only assertion.
- **Missing `scdoc` → fail the commit** (exit `EX_UNAVAILABLE`, kind `MissingRequirement`). The hook is scoped to fire only when the man sources change, so it never blocks unrelated commits; editing `man/cog.1.scd` without the tool to regenerate it is exactly what the gate should catch. This changes today's silent-skip behavior — intentional.
- **Pre-commit hook is a fixer**: it runs `bin/cog man-build` (write mode). On drift, pre-commit's built-in "files were modified by this hook" detection fails the commit with the corrected `man/cog.1` ready to re-stage. Consistent with the repo's existing `end-of-file-fixer` / `trailing-whitespace` fixer hooks.
- **`just man` delegates to the hook**: `pre-commit run man-build --all-files`. This is the literal "make just call this hook" and is consistent with `just lint` (`pre-commit run --all-files`) and `just test` (`pre-commit run test-unit ...`). Note: like `just lint`, it will exit non-zero when it actually had to regenerate the file — that is the established convention here, not a bug.
- **Layering**: `cog man-build` is the SoT mechanic; the pre-commit hook wraps it; `just man` calls the hook. Exactly one `scdoc` invocation exists in the codebase (inside `cmd_man_build.sh`).
- Adding a command requires updating the command-surface mirrors and two hardcoded help snapshots (see Steps 3 and 7). The existing `man source lists every command` test (help_snapshots.bats:286) is kept — it is a complementary gate (`.scd` covers all commands); the new work guarantees `.1 == scdoc(.scd)`.

## Rejected Alternatives

- **Keep the scdoc logic in the justfile, add a separate bats drift check.** Rejected: violates the skill/script boundary (`docs/decisions/0008-skill-script-boundary.md`, `AGENTS.md`) — deterministic mechanics must live in a `cog` subcommand, and it would duplicate the scdoc invocation in two places (justfile + test) rather than one SoT.
- **Check-only hook (read-only, fail with message).** Rejected by user choice in favor of the fixer pattern, which auto-regenerates and matches the repo's other fixer hooks.
- **Skip when scdoc is missing (preserve current behavior).** Rejected by user choice; a gate that silently skips is not a gate.
- **A shared `cog::fn::*` helper for the scdoc call.** Rejected: the logic is used in exactly one place. The contract says move to `lib/functions/` only when two command modules need the same logic. Keep it in the command module.

## Risks & Edge Cases

- **Self-referential man page** — `man/cog.1` must be regenerated _after_ `man/cog.1.scd` gains its own `man-build` entry (Step 3 before Step 4), or the page omits the command. Handled by step order.
- **Snapshot padding** — the help column width is driven by the longest command name; pasting exact `cog --help` output (Step 7) avoids brittle hand-padding. Needs handling.
- **`just man` non-zero on regenerate** — delegating to a fixer hook means `just man` exits non-zero whenever it actually rewrote the page. Accepted: consistent with `just lint`. Document nothing extra; it is the established convention.
- **scdoc output stability vs other fixers** — the committed `man/cog.1` already passes `end-of-file-fixer`/`trailing-whitespace`, so scdoc output does not fight them. If a future scdoc version changes formatting, the `man-build` hook regenerates and those fixers run after it in the same pre-commit pass. Accepted.
- **Hook fires only on man-source changes** — a contributor who adds a new command but forgets to touch `man/cog.1.scd` is still caught by the existing `man source lists every command` test, not by this hook. The two gates are complementary by design. Accepted.
